1. 收拢设备会话状态

Strong

最高 leverage；多处写入同一组设备状态。

pages/devicebinding/devicebinding.js · utils/deviceService.js · utils/http.js · utils/storage.js

Before · 分散而浅

flowchart LR
P[devicebinding page] --> G[getApp globalData]
D[deviceService] --> G
H[http] --> G
P -. token/reset .-> S[storage]
H -. 401/reset .-> P

After · 一个 deep module

small interface · device session
绑定、当前设备、token 选择、清理规则
implementation 内部消化 globalData / storage

Problem
页面、http、deviceService 都会重新拼出 token 和 reset 规则；interface 隐式且 shallow。

Solution
将状态转换、持久化和清理集中到一个前端 module；页面只保留视图状态。

Benefits
locality 集中规则；leverage 覆盖多个调用点；测试只穿过一个 interface。

2. 收拢联系人数据整形

Strong

字段名已修正，但 identity、校验和缓存仍泄漏。

utils/deviceService.js · utils/validators.js · pages/device-detail/device-detail.js · utils/storage.js

Before · 数据规则泄漏

flowchart TB
R[remote contact data] --> M[deviceService mapping]
M --> I[index id]
P[device-detail page] --> V[duplicate phone regex]
P --> C[contactNameCache]
I -. reorder risk .-> P

After · 数据 module 加深

联系人 interface
normalize · validate · stable identity
cache fallback · add/remove orchestration

Problem
页面重复 phone 校验、缓存写入和 index id；返回顺序变化会影响删除目标。

Solution
前端 module 统一 normalize、校验、稳定 identity 和缓存策略；后端保持不变。

Benefits
locality 一处修改；leverage 覆盖列表和详情；测试覆盖多种数据形状。

3. 让 http module 吸收请求策略

Worth exploring

收益高，但应排在设备会话之后。

utils/http.js · utils/storage.js · utils/validators.js · pages/login/login.js · pages/devicebinding/devicebinding.js

Before · transport 与策略纠缠

sequenceDiagram
participant P as page
participant H as http
participant W as wx
participant A as app state
P->>H: request
H->>H: token check
H->>W: request
W-->>H: 401 / business code
H->>A: logout/reset
H->>P: modal/toast/navigation

After · seam 清晰

页面 interface
⋮⋮ seam
http policy module
transport / auth failure / business result
⋮⋮ seam
WeChat adapter

Problem
小 interface 背后同时做 token、全局清理、弹窗、导航和业务码处理，测试必须伪造 wx 与 app。

Solution
仅重排前端 implementation：集中 transport 结果、认证失败和界面提示；后端协议不变。

Benefits
locality 集中失败策略；adapter 可替换；减少页面副作用知识。

Speculative

仅在二维码流程仍会扩展时做。

pages/devicebinding/devicebinding.js · utils/validators.js；后端不纳入改动

Before

Benefits
locality 集中输入规则；round-trip 测试直接；后端风险为零。

TOP RECOMMENDATION

先探索「收拢设备会话状态」

它同时触及三个近期热点；一次 deepening 能最大化 locality 与 leverage，并为联系人与请求策略留下更清晰的 seam。
